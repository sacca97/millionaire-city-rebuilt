## Differences: best-guess causes
1. **Investment event not registered on claim (the mission blocker).** Original: `update_pollmanager add investment` and `add investmentDone` after each success claim, `add investment` after each fail. Ours: none.
   Cause: `apps/client/src/ui/social/invest.ts:269-276` (`finish`: sends `invest_results`, applies the reward, no `register`) used by `p.on('close', finish)` at :291 and :302.
   Original: `decompiled/scripts/com/dchoc/dollars/GUI/PopupInvestSuccess.as:99-100` (investmentDone + investment) and `PopupInvestFail.as:82` (investment).
   Our counter `apps/client/src/ui/missions/system.ts:155-157` (`register`) exists, but nothing calls it for these events. Effect: counter stays `investment/7`, 66 never reaches Reached.
2. **invest_results payload has no `type`.** Original `{fExtId, success, type:5}`, ours `{fExtId, success}`. Cause: original forwards the task params incl. `type` (`decompiled/scripts/com/dchoc/dollars/model/userdata/UserDataFacadeOnline.as:664-665`, `INVEST_TYPE_RESULTS`=5 at UserDataFacade.as:222); ours sends `game.commands.query('invest_results', { fExtId, success })` at `invest.ts:270`. Probably harmless (the server ignores it), not verified.
3. **Reward command.** Ours sends `update_money invest_reward` after each claim (`invest.ts:273-274`, `applyGain`). Original sends no money command; its coins reach the save late. Original shows `,000` on screen after claim 3 but the saved DCCoins is 735000 (`10-04-2-after-close.png`, saves). Original save/reload lag, cause unknown (save timing, not product code we read).
4. **Mission 66 completion chain.** Original: `update_missions sku 66` (x2) and the storage reward `decorations_special_22`; ours none, as 66 is never completed. Consequence of 1.
5. **Mission 44 chain order** (`#14..#18` in the update_missions diff): original 64/68/44/45, ours 68/44/45/64. Cause: the reward-popup queue (`MissionSystem` update chain, `apps/client/src/ui/missions/system.ts` ~L160-170) vs the original's `PollManager` update order. Not checked further.
6. **companyValue / compValueGain.** Original saved `companyValue` 720000 (the 3 claims' company value is not in the save); ours 1207000. Same class-wide pattern as C24-45, C31-1 (`compValueGain` 0 vs X). Cause not determined.
