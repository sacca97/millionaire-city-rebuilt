## Changes made in this pass

- `PollEvent.addEvent` now appends every threshold in definition order, including duplicate thresholds, matching the original implementation. Current default and alt mission sets do not contain a shared event with out-of-order or duplicate thresholds, but preserving source semantics avoids silent divergence if definitions change.
- Client mission parsing retains both reward variants and applies the profile's `missionAltReward` value before building missions.
- Server reward fallback uses `missionAltReward` when paying a mission, so a variant that substitutes an item does not also grant the base coin reward.
- Startup now checks saved coins, cash, and company value against earn/beat thresholds, matching `Profile.eventsBuild` after the original rebuilds PollManager. Mission updates are serialized when rewards change profile values, preventing nested mission updates from reordering chained rewards.
- Added focused tests for definition-order/duplicate threshold behavior, reward selection, and the server's group-2 item payout.

## Oracle status and remaining work

Focused oracle flows ran on isolated bases 31853-31856 (original) and 31863-31865 (rewrite). The rewrite build is at `/tmp/mcity-mission-parity/dist` from a separate `--outDir`; the isolated rewrite server serves it via `MCITY_CLIENT_DIST` so the client and `/Game` API share an origin. `vite preview` does not apply the API proxy and was unsuitable here. Each run's evidence was copied to `/tmp/mcity-mission-parity/` for comparison because the harness's `tools/oracle/out/flow` directory is reused and overwritten by subsequent runs. An initial original-run attempt hit sandbox EPERM on a `tsx` IPC socket; the authorized original runner then completed.

Phase A is complete. Phase B has these row-level paths so far: fully triggered/claimed/reloaded mission IDs 1, 4, 5, 6, 35, 43, and 44; claim/reload only for 2, 20 (group 2), and 47. New instruction expands required scope to all 318 definitions (87 default and 231 alt); `docs/missions-complete-checklist.md` tracks each row. Remaining work includes the other 308 rows' trigger/claim/reload coverage, and resolving the current move-selection issue. No mission type or external interaction is excluded from the expanded scope; neighbor/rival/partner/investment interactions need deterministic fixtures or an evidence-backed blocker. Do not treat this ledger as full parity completion.
